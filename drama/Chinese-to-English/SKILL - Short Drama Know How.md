# Short-Drama Know-How Learning

Treat learning as qualitative research jointly conducted by screenwriters, motion-comic studios, and writer-directors—not as term-frequency mining.
First understand how a complete project communicates dramatic intent into executable text production specifications, then decide what knowledge is transferable.

## Lock Boundaries Before Starting

Read nonpublic sources only when a maintainer actively invokes this skill and the current session already provides authorized read-only access.
Keep connection details, credentials, source names, and private cards in the isolated workspace designated by the maintainer; never write them into this skill,
the public skill tree, public candidates, or evaluation fixtures. If authorization is absent or read-only status cannot be confirmed, stop reading the source and rehearse the process only with synthetic material.

This workflow studies only text and its version relationships. It may read creative briefs, story structure, screenplays, asset/continuity ledgers, image prompts,
storyboard/keyframe text, video prompts, and review and revision records. It does not generate, render, download, or inspect images, audio, or video.
The public runtime never connects to nonpublic sources and performs no media generation.

## Core Principles

- Let the agent judge genre context, character desire, causality, information gaps, emotional progression, performable action, shot intent, and production tradeoffs.
- Delegate only deterministic steps—such as format validation, file comparison, deduplication, and privacy scanning—to existing tools. Do not write rule-matching scripts for creative semantics.
- Use statistics only to describe the selectable sample, identify coverage gaps, find anomalies, and schedule the next reading. Never infer creative rules directly from frequency, ranking, or correlation.
- Every knowledge candidate must carry evidence, counterexamples or failure cases, conflict explanations, scope boundaries, and confidence. “Common” does not mean “effective.”
- Propose only the smallest reviewable public change at a time. Never add it directly to a public skill before blind testing and independent review.

## Workflow

### 1. Establish Read-Only Authorization and an Isolated Workspace

Record the current round's purpose, permitted text scope, prohibited content, output location, and destruction requirements. Test one read-only action
without echoing connection information. Create a private research directory and a separate de-identified candidate directory; initially leave public directories unchanged.

### 2. Select Samples by Coverage Gap

First inspect the smallest index or directory information permitted by the maintainer. Seek gaps, control groups, and anomalous samples across genre, audience promise, core mechanism, length stage, production format,
visual language, scene function, prompt responsibility, completion status, and revision state. Statistics may answer only
“what should be read next,” not “how should this be written.”
Prioritize a deliberately varied sample rather than reading only the most popular, most common, or easiest-to-query projects.

### 3. Qualitatively Read the Complete Project Chain

Read each project from upstream intent to downstream textual deliverables: creative/adaptation constraints → story engine and episode design → episode screenplay →
characters, locations, props, and continuity → image prompts → storyboard and keyframe text → video prompts → review, revisions, and delivery notes.
If a layer does not exist, explicitly record it as missing; do not fill it from another project or common sense.

Trace the same promise throughout: how expectations are established, how obstacles and information gaps are created, which performable actions advance the characters, how turns are prepared,
and how shots/prompts preserve rather than rewrite dramatic intent. Write cards only after reading the complete chain; do not substitute bulk keyword matches for reading.
For card fields and synthetic examples, see [cards-and-coverage.md](references/cards-and-coverage.md).

### 4. Write Private Observation / Decision Cards

Write an observation card first, rigorously separating direct observation, agent interpretation, and unknowns. Then write a decision card recording whether a candidate should be formed,
why its scope was narrowed, and which alternative explanations exist. Bind every card to the same project chain with a stable internal reference that reveals no content,
but never include private cards in the public skill package.

### 5. Build a Genre × Mechanism Coverage Matrix

Use “genre/audience promise” as one axis and mechanisms such as expectation-building, conflict escalation, information release, relationship turns, reversal payoff, episode-end pull,
performable action, shot handoff, and continuity as the other. For prompt research, add layers for production format/visual language, scene function,
prompt responsibility, and version role. Record supporting cards, counterexample cards, boundaries, gaps, and the next sample in each cell—
not occurrence counts or success rates. For the matrix format, see [cards-and-coverage.md](references/cards-and-coverage.md).

### 6. Compress Conclusions with Counterexamples, Conflicts, and Scope Boundaries

Actively seek failures of the same mechanism, exceptions within the same genre, alternative explanations for the same outcome, and cases that work upstream but cannot be produced downstream.
When conflicts remain unexplained, retain candidate status rather than voting by majority. Rewrite “this is always true” as “under these audience promises, character states, and production constraints,
this mechanism may solve this problem; switch methods or do not use it when these signals appear.” For detailed criteria, see
[synthesis-and-promotion.md](references/synthesis-and-promotion.md).

### 7. De-Identify and De-Copy

Delete or abstract source names, character names, proprietary settings, original sentences, rare combinations, exact values, paths, addresses, identifiers, and connection information.
Decompose surface-level plot beats into “audience state → dramatic problem → optional mechanism → observable effect → failure boundary,” then rebuild examples with an entirely new genre, character relationship,
scene, and wording. If the idea can be expressed only by retelling the source content, do not place it in a public candidate.

### 8. Form a Public Reference / Rubric / Synthetic Fixture Proposal

For every candidate package, propose all of the following: a concise reference change, a rubric capable of locating evidence and failure modes, a wholly synthetic
fixture that does not resemble any source, the tasks expected to benefit, and potential side effects. Keep the proposal in the maintainer's staging area first; do not modify the public suite directly.
Public candidates must not require runtime access to nonpublic sources or claim that text proves real media effects.

### 9. Run a Fresh-Agent Blind Forward Evaluation

Have a fresh agent that has read none of the private cards, original projects, or expected answers complete the same set of synthetic tasks using only either the public baseline or an anonymous candidate.
Blindly evaluate its dramatic judgment, genre fit, production executability, ability to vary, and tendency to apply templates mechanically. Run
[blind-forward-eval.md](references/blind-forward-eval.md); do not leak the candidate author's conclusions into the prompt.

### 10. Submit to an Independent Reviewer

A reviewer uninvolved in the current round's extraction, synthesis, or candidate writing must recheck evidence sufficiency, counterexamples, scope boundaries, de-identification, de-copying,
blind-test design, and public-runtime boundaries. The candidate author cannot approve their own work. Return any candidate with unresolved leakage, close imitation, mechanization, or evidence gaps.

### 11. Promote / Retire

Only after a candidate passes fresh-agent blind forward evaluation and independent review—and its reference, rubric, and synthetic fixture agree—may the maintainer promote
the smallest change into public materials. Retain a decision record and rollback instructions containing no private content.
If later counterexamples show the candidate is too broad, blind testing shows no benefit, or it induces templating, narrow, replace, or retire it; do not conceal knowledge changes through silent deletion.
