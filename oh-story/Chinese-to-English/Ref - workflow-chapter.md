# workflow-chapter.md: Single-Chapter Manuscript Workflow (Phases 4–5)

This file defines the complete process for “writing one manuscript chapter.” After SKILL.md routes to Phase 4, follow this file. Daily batch writing uses `workflow-daily.md` to control batches and tracking transactions, while every chapter still follows this file.

Project structure, the artifact-mapping table, missing-file handling, and the authority order for comparable analysis appear at the beginning of Phase 4 in `SKILL.md` and are not repeated here (SKILL.md always remains in context).

Every agent mentioned here checks only the canonical directory for the current environment. Antigravity uses `.agents/agents/agent-name/agent.md` (`agent-name` is the target agent's name), plus `invoke_subagent` and the identically named `TypeName`; other environments use their respective agent tools.

---

## Single-Chapter Writing Process

When the user is ready to write a chapter:

1. **Check the detailed outline**: Read `大纲/细纲_第{N}章.md`, then read the current plot unit (unit ID/position, volume contract, primary thread/results, endgame-trump-card boundary, and risk level) from the corresponding `大纲/卷纲_第X卷.md`. If it does not exist or lacks required fields for the current chapter blueprint, **build or complete the detailed outline before drafting**; never skip it and write the manuscript directly. When completing it, use the event plan and context for this chapter from the volume outline to supply stage position, structural formula, prohibited early releases, content summary, plot arrangement, character relationships/order of appearance, plot elaboration, and ending design. Write `[待补充]` for anything unsupported by existing evidence; never fabricate subplots or relationships. Afterward, follow `artifact-protocols.md` and run `check-outline-contract.js` for structural acceptance. If it fails, add only the named fields and validate again.
2. **Load context** (select as needed; when missing, follow each item's handling and “Missing-File Handling” in Phase 4 of SKILL.md. Skip only optional nonprimary artifacts explicitly marked as such. Optional shortcut: When the relevant agent is deployed, spawn story-explorer once to retrieve context. Prompt: `项目目录：{dir}\n查询类型：context_load\n查询参数：准备写第 {N} 章\n追踪状态：last_committed_chapter={check 的值}，state_revision={check 的值}`):
   - (1) `正文/第{N-1}章_*.md` — previous chapter's manuscript
   - (2) `大纲/细纲_第{N}章.md` — this chapter's detailed outline (including hook design)
   - (2a) `大纲/卷纲_第X卷.md` — current plot unit, volume contract, and endgame reserves (primary thread/results and endgame-trump-card boundary)
   - (3) `tracking_commit.py check` + `追踪/上下文.md` — when `check` emits no ERROR, it passes. Take `last_committed_chapter` / `state_revision` from its compact JSON; do not add full state to the prompt. Retrieve pending foreshadowing from `## 活跃伏笔`, current character state from `## 核心角色状态`, and hard next-chapter commitments from `## 下一章承诺`
   - (4) `设定/角色/{相关角色}.md`, `设定/势力/{相关势力}.md` (when present) — characters and factions involved in this chapter (filtered by detailed-outline appearances)
   - (5) `拆文报告.md` under the comparable-title path (following comparable-title path resolution) — comparable reference
   - (6) `对标/{对标书名}/原文/第{N}章_*.md` (when present) — corresponding-position chapter reference
   - (7) `参考资料/{topic}.md` (when present) — historical research produced by story-researcher
   - (8) `剧情/故事线.md` under the comparable-title path (following comparable-title path resolution) — plot-unit index used to identify the units involved in this chapter
   - (9) `剧情/{相关剧情单元}.md` under the comparable-title path (following comparable-title path resolution) — select plot-unit files relevant to this chapter from the index
   - (10) `设定/世界观/*.md` under the comparable-title path (glob; following comparable-title path resolution) — reference the topical worldbuilding produced by the current deconstruction; if the directory is missing, record the gap and skip this item rather than reading a flat legacy path
   - (11) `剧情/情绪模块.md` under the comparable-title path (following comparable-title path resolution) — reader needs/emotional engine, power-fantasy formula framework, and reproducible modules; if absent, follow “Missing-File Handling” in Phase 4 of SKILL.md, set `missing_primary_contract`, and stop preparation
   - (12) `剧情/节奏.md` under the comparable-title path (following comparable-title path resolution) — key-information progression, emotional triggers, and eruption pacing; if absent, follow “Missing-File Handling” in Phase 4 of SKILL.md, set `missing_primary_contract`, and stop preparation
   - (13) `设定/题材正文提示卡.md` (when present) — this book's manuscript-level genre card; if absent, generate `genre_prose_card` on demand using `设定/题材定位.md` + the `references/genre-prose-cards.md` index + the single-genre card directory `references/genre-prose-cards/` (genre classification first) + `references/style-genre-modules.md` (fallback), without blocking writing
3. **Prewriting preparation** (the following three steps apply the core method to a single chapter: filter state → retrieve modules → confirm intent):
   - **State filtering**: Take current characters from `## 核心角色状态` in `追踪/上下文.md`, foreshadowing that must be resolved/advanced from `## 活跃伏笔`, and mandatory commitments from `## 下一章承诺`, then output the section memo (see state-tracking.md). For a long-absent character, read `追踪/角色状态/{名}.md` by name; inspect chapter deltas only when tracing the reason for a change. If the continuation status card or metadata is absent, follow the current workflow-daily protocol rather than handwriting replacement files
   - **Module, genre-card, and style retrieval**:
     - ① What is this chapter's target emotion? ② Which technique from which reference file will it borrow? ③ In which passages will it be used? If these cannot be answered → reread the reference before drafting
     - (a) **Emotion-module retrieval**: Following “comparable-title path resolution,” read `{对标书路径}/剧情/情绪模块.md` and select the one `selected_emotion_module` closest to the chapter's target emotion (reader need, trigger, dramatic unit, replaceable elements, anti-copying reminder). If absent, set `missing_primary_contract: true`, return a specific `repair_action`, and stop preparation
     - (b) **Pacing retrieval**: Read `{对标书路径}/剧情/节奏.md` and select one `rhythm_reference` (key information → expansion technique → emotional trigger → eruption/cooldown). If absent, set `missing_primary_contract: true`, return a specific `repair_action`, and stop preparation
     - (c) **Genre prose-card retrieval**: Prefer `设定/题材正文提示卡.md`; when absent, first read `设定/题材定位.md` + the `references/genre-prose-cards.md` index, match the primary genre exactly, and read only the corresponding single-genre card from `references/genre-prose-cards/` (such as Urban High-Concept / Wealthy CEO / Period / Boys' Love; a low-confidence card must be marked as such during intent confirmation and requires calibration against a same-genre comparable). If nothing matches, read the general genre module in `references/style-genre-modules.md`. For cross-genre work, extract 3–5 primary-genre rules and 1–2 secondary-genre rules, creating a short `genre_prose_card` (genre boundaries, core logic, reader expectations, central satisfaction/emotion, manuscript implementation, early/middle/late strategies, pacing density, scene granularity, prohibited drift, chapter-specific choices, card confidence). The genre card constrains only manuscript-level genre flavor; it does not alter detailed-outline plot, override `selected_emotion_module` / `rhythm_reference` / `设定/文风.md`, or expose card names/tags/confidence/items/compliance self-assessment in the manuscript. Use it only for internal calibration
     - (d) **Style retrieval**: First read `设定/文风.md` directly (not through explorer). If it has substantive content (≥200 nonwhitespace Chinese characters, or contains sentence-length / punctuation / dialogue / anchor / tone sections with executable constraints: ratios / examples / prohibitions or preferences), set `custom_style=true` and enter “custom-style mode.” It becomes the authoritative style foundation (sentence length / soft punctuation / subtext / emotional alternation), while comparable/deconstruction `文风.md` becomes a reference only (anchors + sentence-length fallback). Treat empty / whitespace-only / title-only / placeholder stubs (todo / pending / ___) as nonexistent. Otherwise, follow “comparable-title path resolution” and read `{对标书路径}/文风.md` (priority: `{项目}/对标/{书名}/`, fallback: `拆文库/{书名}/`). With multiple comparables, read the `主对标书` field from `设定/题材定位.md`. **If custom-style mode is not active and** no style file exists → **fail fast** with: “对标书 X 缺少 文风.md。请用 `/story-long-analyze` 跑 Stage 6 生成文风，再 `/story-import` 同步。” Do not generate it inline (custom-style mode prevents this failure; missing emotion/pacing axes still block independently through `missing_primary_contract`)
     - (e) **Select a matching chapter**: In `{对标书路径}/章节/*_摘要.md`, grep for `基调：(紧张|轻松|悲伤|热血|爽|甜|温馨|恐怖|压抑|其他)` (full-width colon) and choose Chapter K based on the target emotion. When several chapters share a tone, first compare payoff type, then the number of plot beats/estimated source-chapter length against this chapter's target, and finally choose the lowest chapter number. Read `{对标书路径}/章节/第K章_摘要.md`; if `第K章_深度拆解.md` exists for the same chapter, read it too. Otherwise, fall back to the Golden Three Chapters' in-depth analysis or reusable techniques in the style file. Do not fail because a nongolden chapter lacks in-depth analysis
     - (f) **Structured module retrieval**: Search the comparable's structured subdirectories (characters/plot/worldbuilding) for modules relevant to this chapter's plot. If anything conflicts with `剧情/情绪模块.md` / `剧情/节奏.md`, the authoritative files prevail; record the `conflict`
     - (g) Output “primary comparable retrieval summary + secondary comparable retrieval summary + selected_emotion_module + rhythm_reference + genre_prose_card + style-retrieval instructions + source anchor quotation” as narrative-writer input. **With multiple comparable titles**, follow `references/cross-book-recall.md`: The primary comparable supplies style, source anchors, selected_emotion_module, and rhythm_reference; secondary/reference comparables supply structured summaries under a stage budget. Do not limit registered titles or read a secondary title's `文风.md` / source text; when over budget, trim entries rather than title records.
     - **Shortcut**: When story-explorer is deployed in the project, it may retrieve style/module material in one call.
       - Confirm that story-explorer is deployed according to the rules at the top of this file.
       - Query type: `benchmark_style_load`; pass the project directory, chapter number, target tone/length, and payoff type.
       - Required return values: `style_profile_path`, `style_profile_summary`, `selected_emotion_module`, `rhythm_reference`, source paths, matching chapter, anchor passages, and `gaps`.
       - If `gaps.missing_primary_contract` is true, apply `repair_action` first; do not generate manuscript prose.
       - The main session separately reads `设定/文风.md` directly: When substantive, use it as this book's style foundation, but it does not excuse missing emotion/pacing.
   - **Confirm instructions**: Combine the detailed outline, section memo, and module-retrieval result into one sentence stating the chapter's intent.
	     - A new-format detailed outline must consume: stage position, unit ID/position, protagonist objective/key choice, structural formula, prohibited early releases, content summary, plot arrangement, character relationships/order of appearance, plot elaboration, and ending hook, checked against the current plot unit's volume contract, primary thread/results, and endgame-trump-card boundary.
	     - **Detailed-outline-first boundary**: The manuscript may expand only events, characters, conflicts, foreshadowing, and the ending hook already present in this chapter's outline. Never invent a new main plot, character, twist, or later-chapter development merely to add length or “make it more exciting”; necessary transitional actions may serve only listed plot beats. A hook must not prematurely reveal later-stage truths, trump cards, relationship conclusions, or final conflict. Conversely, the outline is a contract for “what happens,” not the shape of the manuscript: Prose may reorder narration and combine/interweave beats; it need not devote one paragraph to each beat or follow a five-part sequence. Dramatize each point as a scene instead of copying its summary wording (see “From Detailed Outline to Manuscript” in writing-craft.md).
	     - **Semantic deduplication of the detailed outline**: When the same requirement appears in the central event, five-part structure, plot arrangement, and plot beats, count it as one semantic point. Merge it before generation; do not treat repetition as emphasis or restate outline phrasing item by item. For example, if several places say “do not bring a camera; listen first, then decide whether to film,” deliver it once through a natural action or character judgment rather than two explanatory rounds such as “As for whether to film, and how…” and “No camera, no interview light.”
	     - Before a satisfying move, include an identifiable crisis/expectation setup; in a power-display/comeuppance/revelation chapter, give present supporting characters differentiated reactions.
	     - In high-pressure/life-or-death/grief beats, tighten dialogue voices: The comic-relief character yields, informational characters do not become exposition machines, and each line responds to the other person's emotion.
	     - Check task obstacles: If the chapter includes “official business being blocked,” it must change information, relationships, cost, choice, or foreshadowing; otherwise do not force it in.
	     - Contract-risk check: Using `references/reader-contract-and-progression.md`, classify as contract-safe / needs reinforcement / contract breach. If a supporting character, institution, or coincidence takes the protagonist's spotlight/gain without a visible exchange, repair the outline before writing.
     - Example: “Fast-paced comeuppance—the bill is exposed → interrogation → counterevidence → public cost; readers have waited three chapters, so this chapter must land the punch completely.”
4. **Research** (as needed): When an external fact requires verification and story-researcher is deployed, spawn it to search and write into `参考资料/`; otherwise the main thread performs the research. Continue writing only after research finishes.
5. **Title precheck**: Read the chapter title from the detailed outline before drafting. If it duplicates or clearly repeats an existing chapter title, rename it around this chapter's central event and synchronize both the outline title and manuscript filename.
6. **Writing and the sole checkpoint**: Divide approved plot beats into two consecutive groups in narrative order. In the same session, write the first group to a temporary segment, then run `{PYTHON} {skill 根}/scripts/storyctl.py wordcount checkpoint --file {前组临时文件} --target {字数目标} --chapter {N}` once and only once. Return `actual`, `remaining_user_range`, and the original latter-group plot beats to the writer, with explicit instructions:
   - Complete only the remaining plot beats; do not add a separate event, character decision, relationship change, reveal, or subplot for length.
   - Stop when the remaining plot beats are complete, even if still short; do not add plot.
   Assemble both segments into the final manuscript once. Do not use per-beat quotas, word-count retries, complete rewrites, or post-save expansion.
   - **Manuscript metadata isolation**: `章节：第{N}章`, `上一章：正文/第{N-1}章_*.md`, `匹配第K章`, `细纲文件`, and similar metadata exist only to locate material. Outside the title line, the manuscript must not contain engineering terms such as `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者`. When referring back, use an event anchor or relative time the character can perceive; for example, “it hurt more than the three seconds of gunfire in Chapter 1” must become “it hurt more than those three seconds of gunfire.” Exception: Preserve such terms when characters genuinely read/discuss “Chapter X” within the story world or are genuinely authors/readers discussing reader identity.
7. **Execute the manuscript**:
   - Confirm narrative-writer is deployed according to the rules at the top of this file.
   - If available, spawn `Agent(subagent_type: "narrative-writer", prompt: ...)`, passing only material required for this chapter:
     - Project directory, chapter, detailed-outline file, previous chapter, output path.
     - Prewriting output: section memo, emotional objective, involved characters, reference technique.
     - Primary comparable/deconstruction paths and primary/secondary comparable retrieval summaries.
     - `selected_emotion_module`, `rhythm_reference`, and source paths.
     - `genre_prose_card` (genre prose-card summary containing only chapter-relevant items).
     - Style path, style-retrieval instructions, and source anchor passages.
     - `author_preferences`: The `prose_style` / `story_design` items from author-memory `query` results that match this chapter. Omit when absent; never put a complete profile or unconfirmed item into the prompt. Absorb them naturally as low-priority tendencies rather than displaying or maximizing item-by-item matches, and never sacrifice coherence, pacing, or length.
     - Stage position, chapter structural formula, information this chapter may release, information prohibited from early release.
     - Length target, `visible_chars_v1` metric, and hard format constraints. After the first group, the machine supplies the remaining user range once; the writer never estimates it or fills per-beat quotas.
     - Detailed-outline-first boundary (content layer): Expand only this chapter's outline and invent no new plot. Every plot beat must land independently—none omitted or merged into one sentence. Never automatically add to the outline, expand, or rewrite merely to chase length; Step 8 measures actual length.
     - Manuscript shape (shape layer): The subagent determines placement, order, and how many passages to use. It may disperse/reorder beats or weave adjacent points into one continuous action; do not march through one paragraph per point or copy outline wording into narration.
   - Do not copy this file's full rule set into the prompt; rely on loaded references and the narrative-writer template for details.
   - Within the same session, the agent writes the two temporary segments using the process above. After the main session confirms they consume only approved plot beats, assemble and write `正文/第XXX章_章名.md` once. If the agent is not deployed, the main thread follows the same process.
8. **Asymmetric closure**: Run `{PYTHON} {skill 根}/scripts/storyctl.py chapter check --project {项目根} --chapter {N}`; rerun after file changes and do not persist decisions.
   - In band + pass → `chapter commit`; fail / `invalid` → stop.
   - `under` + pass → show `accept-current-length / revise-outline-or-target / discard`; do not expand/retry. The acceptance command rereads, recounts, and commits atomically.
   - `over` + pass → send deletion ranges with `compress-once` to narrative-writer; perform one net deletion with zero new semantics/contract changes. After the session checks plot beats and hook, recheck. If now in band, commit; otherwise present the same three actions.
9. **Review**: Does the ending provide a reason to continue (a low-pressure/transitional chapter needs only a weak hook or continuing stage objective, not necessarily a payoff)? Does the payoff land (based on chapter function; mandatory for high-pressure/progression chapters)? Two falsifiable checks (when failed, repair only detailed-outline-approved content): ① Is there an identifiable crisis/expectation passage before the payoff? ② In a power-display/comeuppance/revelation chapter, do present supporting characters react differently? After a quality repair, rerun Step 8, but never add new plot through the repair to chase length.
10. **Metadata scan**: Outside the title line, when manuscript text matches `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者`, rewrite it into in-scene expression. Exceptions apply only when characters genuinely read/discuss “Chapter X” inside the story world or genuinely are authors/readers discussing reader identity.
	11. **Prohibited-language scan**: First run the **most-toxic-pattern quick check** (the patterns most often missed in testing; revise every match): ① the entire “not A, (but) B” family—including parallel negation “no X, no Y (, only Z),” reversed “B, not A,” and suppression-then-elevation “He didn't X, nor Y. He only Z”; ② vocal contrast “the voice wasn't loud/high…yet…”; ③ the universal adverbial “, carrying…”; ④ predictive/summary endings “no one knew…,” “(this) was only the beginning/start,” “was bearing down on…,” “was about to begin,” “at this moment…”; ⑤ quotation marks emphasizing short narrative words (he was invited to “check” it). Then review the detector's `formulaic-parallelism` advisory: Cross-paragraph “not A. / nor B. / only C,” `至于X不X，怎么X`, and repeated-verb `不V A，不V B` cannot be skipped even in dialogue; retain only genuine functional expression by a character in the moment. Then check the complete table in `references/banned-words.md`: Replace every tier-one term (frequent AI-like language); replace tier-two terms (infrequent/context-dependent) when frequent, while isolated instances may be judged qualitatively using `references/anti-ai-writing.md`
12. **Update tracking**: After the final `chapter check`, take the latest `state_revision` and construct chapter JSON without `wordcount` according to workflow-daily. For a chapter inside the user band, run `storyctl.py chapter commit`; if the user accepts its natural current length, run `storyctl.py chapter accept-current-length`. Both commands reread the manuscript and target, recount, rerun blocking quality, and atomically commit the concise word-count record with the tracking transaction. Retain the original transaction and rerun it after a write failure; reconstruct it after a validation failure. Repair damaged derived views with a revision as specified in the tracking documentation; never edit them manually. When the chapter first introduces a reusable character/faction, create its static dossier according to Phase 3 of workflow-setup.
13. **Intermediate snapshot** (safety net for long-form writing): After every three consecutive chapters, perform these snapshot actions before continuing:
   - Run `scripts/tracking_commit.py check` to confirm `_tracking-state.json` is valid, chapter records are consecutive and within limits, every derived view matches, and the continuation status card has exactly seven sections and is ≤12,288 bytes. On pass, delete the chapter transaction JSON and temporary segments; on failure, retain the transaction JSON for an identical rerun
   - Use `ls -la 正文/` to confirm the three latest chapter files were written successfully and have normal size (>100 bytes)
   - If a file is absent or abnormally small, rewrite it immediately
   - Continue writing after the snapshot is complete

> **Daily mode**: Automatically skip this step—Step 2 of workflow-daily already updates 上下文.md chapter by chapter.

## Writing-Technique Reminders

| Scene | Technique |
|------|------|
| First 500 Chinese characters | Must contain a hook and cannot begin with weather/scenery (unless the contrast is extreme) |
| Dialogue | Advance plot or reveal character; never exist only to add length |
| Combat | Avoid action logs; write strategy and reversals, not “you punch, I kick” |
| Daily life | Include character interaction and foreshadowing, not only “eating and sleeping” |
| Task obstacle | When official business is blocked, the obstacle must change information/relationships/cost/choice/foreshadowing; compress or delete it when removal causes no loss |
| Payoff delivery | Set up fully and release decisively; the longer readers wait, the more satisfying the release must be |
| Payoff density | One emotionally “satisfying” beat every 3,000–5,000 Chinese characters in high-pressure/progression chapters; not mandatory in low-pressure/relationship/training/information-organization chapters, though every chapter still needs a reason to continue (see “Chapter Positioning and Tension/Release” in references/outline-structure-theory.md) |
| Long-form structural constraint | Follow genre-prose-cards.md and the current genre card's long-range constraints |
| Chapter ending | Every chapter ends with something that makes readers turn the page |
| Emotional validation | After each chapter ask: What should readers feel here? Do they feel it? If not → repair according to chapter function: add conflict or a hook in high-pressure/progression chapters; add relational or emotional texture in low-pressure/relationship chapters; do not add a payoff indiscriminately |

## Authoritative Word-Count Measurement

The default authority is detailed-outline `字数目标` + `visible_chars_v1`: inner band ±12%, user band ±15%; **when the user explicitly supplies minimum and maximum bounds for this run, preserve that range and prioritize it over automatic percentage bands**. There is no pacing floor; a missing target is `invalid`. Commit in-band work, do not expand `under`, and perform at most one net deletion for `over`; when still out of band, the user must accept, change target/outline, or discard. The next chapter reads only the tracking commit.

## Quality Review

Check three dimensions: (1) **Emotional delivery**—does each chapter deliver the target emotion planned in the detailed outline? (2) **Contract risk**—using `references/reader-contract-and-progression.md`, check causal and resolution ownership, four key-beat questions, ownership of expectations, expectation debt, endgame reserves (two overdraft questions), and book-switching debt. Grade chapter progression using the authoritative file's seven states (fast pacing retains a visible-event/payoff floor), judging strength relative to this book's genre and comparables; mark contract-safe / needs reinforcement / contract breach. Repair the manuscript or later outline before proceeding after a breach. (3) **Technical quality**—consistency, format, and prohibited language. Consult the general and long-form checklists in [references/long-chapter-quality.md](long-chapter-quality.md).

**Independent new plot is blocking**: A new dinner, promise, choice, relationship change, subplot, or later obligation blocks; casual talk and micro-connections are allowed. Do not automatically fix, retry, or commit a match; report the outline drift.

**Manuscript metadata scan**: Clear writing-engineering terms outside the title line using Step 10 above before other checks. `check-degeneration.js` deterministically rescans this item.

**Clear within the same run after writing**: Saving the manuscript is not a reporting point—after every save, complete the Step 10–11 scans above, the deterministic closing scripts below, and the narrative-writer review **within the same run**. A chapter is complete only when blocking findings reach zero; never first report “finished” and wait for instructions. The post-write hook automatically scans saved prose for deterministic toxic patterns and sends matches back—that is a safety net, not a replacement, and all hook findings must be cleared in the same run. **Sole exemption**: The user explicitly says “do not remove AI-like prose in this chapter/skip review.” Under the exemption, add `<!-- 去味:跳过 -->` immediately below the chapter title (both the post-write toxic-pattern hook and pre-next-chapter debt blocker recognize it; other safeguards remain active).

**Deterministic closure**: After writing the batch, the main session runs `node scripts/check-ai-patterns.js --check --fail-on=blocking 正文/第XXX章_*.md` and `node scripts/check-outline-copy.js 正文/第XXX章_*.md` (detailed-outline copying rescan) on the actual saved files. Revise blocking matches in the manuscript and rescan. Read each advisory and outline overlap in context, changing it only when genuinely problematic; label functional language `[需复核]`—every item needs a conclusion, but never rewrite mechanically just to reach zero. Add retained outline-overlap language to “Repetition Anchor Lines” in the detailed outline so it is not reported again from the next chapter onward. `formulaic-parallelism` must be reviewed in dialogue too; never skip it merely because the hook does not block dialogue. For `stock-reaction-tic`, apply the four deletion questions from “Four Anti-Cliché Questions” in `writing-craft.md` to every instance. In the delivery summary, report candidate count, deletion count, and the narrative function of every retained item; “checked” alone is insufficient.
Then run `node scripts/normalize-punctuation.js 正文/第XXX章_*.md` (default `--quote-mode keep`) to clean purposeless ellipses, em dashes, double hyphens, and standalone separators; Salted Words quotation marks 「」 are unaffected. The narrative-writer agent does not run these scripts.

**Degradation protection**: After saving manuscript text, run `node scripts/check-degeneration.js --check 正文/第XXX章_*.md`. For blocking issues (repetition, truncation, refusal language, leaked tier-one engineering terms), rewrite only affected chapters, at most twice; if failure remains, show the evidence and ask the user to decide.
Advisories identify suspicious locations only; first read the script's exceptions. Preserve functional in-story system/interface language, repeated livestream comments, repeated dialogue, and similar cases.

### Agent Call: consistency-checker

During quality review, if consistency-checker is deployed, check only the canonical agent directory for the current runtime and spawn it to obtain an S1–S4 report. Prompt: `项目目录：{dir}\n检查范围：{本次写作的章节}\n检查类型：事实冲突+伏笔断线+角色属性不一致`. If unavailable, the main thread checks directly using long-chapter-quality.md.

### Agent Call: narrative-writer (AI-Like-Prose Review)

During quality review, spawn narrative-writer for writing quality and AI-like-prose review when deployed. Prompt: `项目目录：{dir}\n任务描述：审查+去AI味\n检查范围：{本次写作的章节}\n作者偏好：{本章 query 命中的 prose_style/story_design 项}\n删除优先：每条 AI 味项先判能否删除——删后不丢伏笔/钩子/角色/情节/必要信息的直接删，会丢才润色（删除受比例上限与字数下限约束，跌破下限改降AI重写）\n检查项按你自己的 7 Gate、禁止事项与写完后对话自检全量执行，其中否定翻转句式和台词里的工整否定清单不因脚本豁免台词而跳过`. If unavailable, the main thread follows `references/anti-ai-writing.md` and `references/banned-words.md`.

If post-review manuscript revisions change continuity facts, construct a same-chapter tracking transaction with `mode=revision` and run `scripts/tracking_commit.py commit`:
- Use `foreshadow_changes` to update the current row for the same ID rather than appending duplicate history;
- Write timeline changes into `timeline_events`; `_tracking-state.json` derives `作者真相.md` and `读者已知.md` consistently, and author-only secrets must never leak into the reader view;
- Submit the affected central character's complete snapshot through the current chapter along with any central-character state change;
- After transaction failure, retain the original transaction JSON, correct the write environment, and rerun the same `commit`; after success, run `check`, confirm state matches all derived views, delete the temporary transaction JSON, and only then continue writing.
