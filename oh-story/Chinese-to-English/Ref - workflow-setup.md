# workflow-setup.md: Book Setup Workflow (Phases 1–3)

This file provides the complete workflow for “starting a book/building world details/creating an outline,” extracted from Phases 1–3 of SKILL.md.
SKILL.md retains only scenario routing and stopping rules. Before entering any phase, read the corresponding section here and follow its steps.

> Run these three phases only once per book (add incremental material in Phases 2/3 when beginning a new volume). Daily continuation and single-chapter writing do not require this file;
> follow Phase 4 in SKILL.md and `workflow-daily.md`.

---

### Phase 1: Confirm the Subject Direction

**Check the subject-selection decision first**: If `选题决策.md` exists at the project root (produced by Phase 5 of story-long-scan), read it. Use the first-ranked recommendation (highest feasibility) as the starting point and ask the user: “The ranking scan recommends X (breakout reason Y, differentiation Z). Start the book with this?” Check `扫榜日期`; if it is old, warn that “market data may be outdated; consider rescanning.” If the user agrees → carry that subject's genre/selling point/differentiation into Phase 2.
If absent, search automatically once: Beginning at the project root and its parent, search downward no more than three levels for the filename `选题决策.md` (skip hidden directories), sort by mtime newest first, and take the two latest. If found → use AskUserQuestion to list candidates (path + each file's `扫榜日期`, plus “I will provide a path” and “Use none”). When one is chosen → copy it to the project root and read it as above. If “I will provide a path” → ask the user to paste the path and likewise copy it to the project root. If “Use none” → ask the normal questions below. If no file is found → ask once: “Do you have a `选题决策.md` generated by a ranking scan? Put it at the project root or paste its path; otherwise answer the questions below.” If still absent → proceed with the normal questions.

If the user already has a direction → skip the direction questions below, but still perform “Comparable Context Loading” (including comparable discovery) before entering Phase 2.

If the user has no direction:

Ask: **“What do you want readers to feel? Is there a book you want to use as a comparable? What are your strengths (strong concepts/strong prose/strong pacing/rich life experience)?”**

#### Comparable Context Loading

> Definitions of the **deconstruction-library/comparable relationship** and **comparable-title path resolution** appear under “Path and Terminology Conventions” in SKILL.md. This file and Phase 4 share the same rule.

**Comparable discovery (before reactive loading below)**: Whether or not the user names a comparable, scan `拆文库/` first and recommend proactively by genre rather than waiting for the user.

1. Run `ls 拆文库/` (data source) and list books under project `对标/` (reference view). First identify the current work using the project directory name, `.active-book`, and its information in `设定/题材定位.md`, then exclude any same-name `拆文库/{当前书}/` or source pointing to the current manuscript. The book's deconstruction analysis generated by story-import to rebuild the project is not a comparable candidate and must not be copied back into `对标/`. If both are empty after exclusions → skip to item 4.
2. Read each book's genre (for short fiction, `genre_detected` in `拆文库/{书}/_meta.json`; for long fiction, the header of `概要.md` or “Genre” under “Basic Information” in `拆文报告.md`), compare it with this book's genre/direction, and label same genre / weakly related / unrelated.
3. If same-genre or weakly related candidates exist → recommend them through AskUserQuestion (candidate books + “Use none” + “Deconstruct another”). One primary comparable provides style/manuscript guidance; the rest become secondary comparables. Record the choice in `主对标书` / `对标书列表` under “Comparable Registry” in `设定/题材定位.md` (Phase 2 saves the file; retain the decision for now), then copy each selected book from `拆文库/{书}/` to `对标/{书}/` according to “First Reference to a Comparable” under “Path and Terminology Conventions” in SKILL.md.
4. If there is no candidate → proceed without a comparable (arrange the outline using the eight-beat model; see Phase 3). If the user wants one, first deconstruct a book with `/story-long-analyze`.

If the user mentions a comparable or a `对标/` directory already exists in the working directory:

1. First identify the current work using the same criteria as item 1 under “Comparable Discovery” and exclude a same-name or current-manuscript-sourced `对标/{当前书}/`; a legacy imported project may contain a historically miscreated self-comparable directory. If no external comparables remain, skip the following steps and continue without one.
2. Following comparable-title path resolution, check `剧情/情绪模块.md` and `剧情/节奏.md`.
3. If either primary artifact is absent, stop, set `missing_primary_contract: true`, and provide `repair_action`: Rerun Stage 3+ of `/story-long-analyze` or rerun `/story-import`. Never substitute `拆文报告.md`, chapter summaries, or the story-thread file.
4. When both primary artifacts exist, first read reader needs/emotional engine and reproducible modules in `剧情/情绪模块.md`, then key-information progression, emotional triggers, and eruption pacing in `剧情/节奏.md`. Use `拆文报告.md` only as a human-readable overview.
5. If character, ordinary plot-unit, or worldbuilding subdirectories exist, retrieve relevant modules on demand during writing.

Match recommendations to the response:
- Strong concepts → recommend: system fiction, multiverse-travel fiction, infinite-flow fiction
- Strong prose → recommend: cultivation, historical fiction, literary urban fiction
- Strong pacing → recommend: urban power fantasy, rebirth fiction, game fiction
- Rich life experience → recommend: industry fiction, urban slice-of-life, farming fiction

#### Agent Call: story-architect

story-architect is a high-level structural-design agent. The main session should handle lightweight genre positioning; invoke story-architect only for complex worldbuilding, multithread structures, heavily engineered reversals, or an explicit user request. After confirming the subject direction, if story-architect is deployed (check whether `.claude/agents/story-architect.md` exists), you may spawn `Agent(subagent_type: "story-architect", prompt: "项目目录：{dir}\n任务类型：题材定位\n查询参数：{用户选择的方向+对标信息}")` to assist with genre analysis and central-premise design. If unavailable, the main thread performs the work.

> **story-architect contract summary (must be attached verbatim when spawning)**: The deployed story-architect agent does not know this skill's `references/reader-contract-and-progression.md` and can align with its schema only through this summary in the spawn prompt. Otherwise, the main thread and delegated output will use different progression rules. Summary:
> - **Endgame reserve boundary**: Endgame trump cards (primary nemesis/ultimate truth/special-advantage ceiling/final identity/central emotional destination) are single-use resources. Unlock them volume by volume and never exhaust them early. Unlock progression steps (realm/level/map/faction tier) one by one according to the remaining tiers; never skip levels.
> - **Two overdraft questions** (if either answer is “yes,” roll back or revise the outline): ① Does this use an endgame trump card that should not unlock in the current stage? ② Does it push a progression thread close to its ceiling with no later step available?
> - **Plot units**: Write plot-unit cards inside the volume outline, including unit ID, one primary thread + several result threads (multiple gains from one battle are permitted), and a chapter-level progression floor (fast pacing retains a visible-event/payoff floor).
> - **Chapter-outline fields**: Every detailed chapter outline must include unit ID/position and protagonist objective/key choice. “Action cost (optional)/ownership of gains” replaces the old “cost fulfillment” field—action cost may be absent and must not be invented; ownership of gains must be visible.
> - **Reader contract and protagonist agency**: The protagonist's irreplaceability depends on causal ownership (a decision/plan/authorization/critical information determines how events happen or turn) + resolution ownership (central gain/recognition returns to the promised recipient). The protagonist need not perform every action personally. Supporting characters may execute local actions but must not silently take promised spotlight/gains.
> - **Four key-beat questions** (ask for every key beat): ① Who decides why/how the event begins? ② Who makes the irreplaceable key choice? ③ Who bears or chooses the key consequence? ④ Who ultimately receives the central gain/recognition/power?
> - The complete rules remain authoritative in `references/reader-contract-and-progression.md`, already loaded by the main session. This is only a compressed version for story-architect; the agent does not deploy that file and cannot read it independently.

### Phase 2: Core Worldbuilding

Starting with the target emotion confirmed in Phase 1, find the corresponding plot pattern within the genre framework, extract reusable modules from the comparable (treat specific characters as functional roles), and populate them with the user's own characters and setting.

Help the user establish these core elements:

```
## 核心设定表

### 基本信息
- 书名：{暂定名}
- 题材/类型：{主类型 + 副类型}
- 目标平台：{起点/番茄/晋江/其他}
- 预计字数：{X} 万字
- 目标读者：{画像}
- 读者契约：{本书承诺的核心阅读快感；参 reader-contract-and-progression.md}
- 主角高光/代理权：{主角不可替代的判断、选择或贡献}
- 核心期待债：{开篇必须偿还的承诺}

### 一句话梗概
{主角 + 目标 + 阻碍 + 反转，一句话概括全书}

### 主角设定
- 姓名：{}
- 年龄：{}
- 核心特质：{2-3 个关键词}
- 金手指/核心能力：{}
- 弱点/缺陷：{让角色更立体的地方}
- 核心动机：{他为什么要做这件事}

### 世界观骨架
- 时代/背景：{}
- 核心设定：{区别于同类作品的独特设定}
- 力量体系：{如果有，简单概括}
- 社会结构：{影响故事的关键设定}

### 核心冲突
- 主线矛盾：{}
- 终极 Boss/终极阻碍：{}
```

After completing the core worldbuilding, create these artifacts (load the corresponding templates in [references/artifact-protocols.md](artifact-protocols.md)):
- **设定/关系.md**: Character-relationship map (see “Four Relationship Types” in character-relations.md)
- **设定/题材定位.md**: Three-part central premise + comparable analysis (see “Central-Premise Analysis” in long-genre-mechanics.md). Keep a two-to-three-row summary in the comparable analysis table; detailed data lives in `对标/`
- **设定/题材正文提示卡.md**: Extract this book's manuscript-level genre card from `设定/题材定位.md` + `references/genre-prose-cards.md` (index) + `references/genre-prose-cards/` (single-genre card directory, prioritize genre classification) + `references/style-genre-modules.md` (general genre supplement). Include only genre boundaries, core logic, reader expectations, central payoff/emotion, manuscript implementation, early/middle/late strategies, pacing density, scene granularity, and prohibited drift; omit general formatting rules and do not override `设定/文风.md`

> **With multiple comparable titles**: Follow `references/cross-book-recall.md`; place secondary-comparable anchors in an appendix to the “Comparable Analysis” table.

### Phase 3: Building the Outline

#### Book Length and Stage Overview (Before Volume Outlines)

Before the volume-level outline, define total book length and stage boundaries as shared constraints for later volume outlines, detailed outlines, and daily outline expansion. Ratios are defaults only and must be adjusted for genre, target length, and comparable pacing rather than applied mechanically.

```
## 全书体量与阶段总览

- 全书总章节数：{X} 章
- 目标字数：{X} 万字
- 全书情绪曲线：{压抑/期待 → 加压/反转 → 爽感/震撼 → 余韵/圆满；标注关键阶段}

### 阶段划分
1. 开篇期（第 {A}-{B} 章，参考 10%-15%）：核心任务 {立人设/立世界/埋主线钩子}；情绪基调 {压抑/期待/惊奇}；阶段结束时读者应建立 {对主角的认同 + 对主线冲突的期待}
2. 发展期（第 {A}-{B} 章，参考 50%-60%）：核心任务 {矛盾展开/支线并行/资源与关系升级}；情绪基调 {期待/紧张/间歇爽感}；阶段结束时读者应建立 {对核心反派或终局矛盾的迫切期待}
3. 高潮期（第 {A}-{B} 章，参考 20%-25%）：核心任务 {核心冲突爆发/多线收束/连续爽点}；情绪基调 {爽感/震撼/反转}；阶段结束时核心矛盾应 {基本解决或进入最终对决}
4. 收尾期（第 {A}-{B} 章，参考 5%-10%）：核心任务 {伏笔回收/关系落定/结局余韵}；情绪基调 {释然/感动/圆满}；阶段结束时主线伏笔应 {回收完毕，结局落定}

### 各阶段节奏公式
- 开篇期：核心任务 / 情绪基调 / 爽点密度 / 伏笔策略 / 冲突层级 / 阶段钩子 / 禁止提前释放
- 发展期：核心任务 / 情绪基调 / 爽点密度 / 伏笔策略 / 冲突层级 / 阶段钩子 / 禁止提前释放
- 高潮期：核心任务 / 情绪基调 / 爽点密度 / 伏笔策略 / 冲突层级 / 阶段钩子 / 禁止提前释放
- 收尾期：核心任务 / 情绪基调 / 爽点密度 / 伏笔策略 / 冲突层级 / 阶段钩子 / 必须回收清单

### 关键节点与钩子链
- 关键转折点：第 {X/Y/Z} 章，各自承担 {事件功能 + 情绪效果}
- 小/中/大高潮：小高潮第 {X/Y/Z} 章；中高潮第 {X/Y} 章；大高潮第 {X} 章
- 阶段钩子链：开篇期结尾指向发展期；发展期结尾指向高潮期；高潮期结尾指向收尾期
```

#### Volume-Level Outline (Full-Book Structure)

```
## 卷级大纲

### 第一卷：{卷名}（约 {X} 万字，{Y} 章）
- 功能：{铺垫/起步/第一个大爽点}
- 所属阶段：{开篇期/发展期/高潮期/收尾期；可跨阶段时写清分界章}
- 卷契约：{本卷承诺的读者快感、主角高光、主要期待债}
- 终局储备：{本卷主推线1条 + 战果线若干（一战多得允许）；本卷解锁哪个终局里程碑、禁碰哪些未解锁底牌，参 `设定/题材定位.md`「终局底牌与升级台阶」小节 与 reader-contract-and-progression.md}
- 剧情单元：{1–3 万字剧情单元卡写在卷纲内，不另建单独文件；字段模板见 `references/artifact-protocols.md`，契约/推进规则见 `references/reader-contract-and-progression.md`}
- 阶段边界：本卷可释放 {信息/关系/能力}；本卷禁止提前释放 {后期核心真相/终局底牌}
- 核心事件：{一句话}
- 起始状态 → 结束状态：{主角从 {A} 变成 {B}}

### 第二卷：{卷名}
...

### 最终卷：{卷名}
- 功能：{高潮 + 收尾}
- 核心事件：{一句话}
```

> **With multiple comparable titles**: Follow `references/cross-book-recall.md`; retrieve secondary-comparable `章节/*_摘要.md` + `剧情/*.md` for volume-level pacing.

> **Comparable-pacing feedback (once before finalizing a volume outline when a primary comparable exists)**: Read `对标/{书}/剧情/节奏.md` for the primary comparable. If absent, set `missing_primary_contract: true`, stop, and instruct the user to rerun Stage 3+ of `/story-long-analyze` or rerun `/story-import`; never substitute chapter summaries, story threads, or the deconstruction report. When present, use “Comparable-Pacing Migration” in references/outline-structure-theory.md to replace the material and arrange the comparable's primary structural beats (quarter point/midpoint/three-quarter point) within this volume's “Comparable Structural Coordinates.” Select passages by primary-comparable plot unit and group the same class by “type/plot-event tags” (see Step 1 in that section). Record selected plot units under “Comparable Plot Reference” in the plot-unit card. If no primary comparable has been registered but `拆文库/` contains a same-genre candidate, return to “Comparable Discovery” in Phase 1 and register it before arranging pacing. If no comparable exists, arrange pacing using eight-beat proportions.

#### Detailed Outlines (Every Chapter in the Book)

⚠️ **Seven outline-safety checks (answer all once per batch before designing each volume/batch of detailed outlines; for individual chapters, repeat only ⑥⑦ and write the risk level into the chapter's “Contract Risk” line rather than answering the whole table again. When adding a plot unit midstream, anchor ⑦'s key events at the unit's quarter point/midpoint/three-quarter point rather than changing the locked volume-scale coordinate table)**: ① What emotion does this volume deliver? Which plot pattern reliably delivers it? ② What is the volume's central conflict? ③ Where does its setup-development-turn-resolution pacing accelerate or slow? ④ Which new foreshadowing must be planted, and how will unresolved foreshadowing from the previous volume be handled? ⑤ Does chapter positioning vary in intensity rather than remaining high-pressure throughout, and are low-pressure + transitional chapters restrained (combined no more than roughly 15%)? ⑥ Where is this volume/chapter within the book's stages; what may be released and what must remain withheld? ⑦ Does reader contract, protagonist agency, expectation debt, and endgame reserves (trump cards/progression steps) rate contract-safe / needs reinforcement / contract breach under reader-contract-and-progression.md? With a comparable, is one key event anchored at each of the quarter point/midpoint/three-quarter point (see “Chapter Positioning and Tension/Release / Comparable-Pacing Migration” in references/outline-structure-theory.md)?

**Outline safety review (order is mandatory; run once per batch across every plot unit and chapter in the batch)**: First use `references/emotional-methods.md` to design the positive emotional engine and core genre fulfillment; then diagnose it using the authoritative file's negative-risk guardrails for protagonist agency/ownership/growth. Through causal + resolution ownership, four key-beat questions, and expectation ownership, the latter checks each plot unit's protagonist objective, key choice, fulfillment ownership, core-asset exchange, institution/faction boundaries, book-switching debt, and progression thread. It does not require the protagonist to perform every action personally. A contract breach requires outline repair; needs reinforcement requires added exchange/setup/cost. Then apply two falsifiable degradation checks: ① If the genre's central object/relationship/problem is removed, does the plot become generic professional advancement or a reskinned story? ② If the protagonist is removed, does the emotional fulfillment remain essentially unchanged? If either answer is “yes,” repair the engine first.

**Every chapter must have one detailed-outline file** (`大纲/细纲_第XXX章.md`); skipping chapters is prohibited.

Build outlines in batches by default: Create the first ten chapter outlines, then **stop** and report “Ready to write Chapter 1/begin daily writing.” Enter Phase 4 only when the user explicitly requests manuscript prose. For rolling outline expansion, follow the numbering rules (see “Batching Detailed Outlines by Plot” in references/outline-structure-theory.md):
1. **Batch boundary**: One batch ≈ one plot unit (5–15 chapters); split a >10-chapter unit into two batches. **First batch = capped at the first ten chapters and may cross units**: Retrieve a crossed plot unit once when building its card; later rolling batches share the card's fixed conclusions for remaining chapters. When entering the final portion of a unit (≤2 chapters remain without outlines), roll forward and outline the entire next unit. Follow a user-specified chapter count/range, though a single batch should still be ≤10 chapters and delivered continuously in batches.
2. **Batch positioning and stage constraints** (write before every outline batch): Identify the stage and plot unit (unit ID) containing the range, the batch progression objective, information permitted for release, information strictly prohibited from early release, and the boundary chapter-ending hooks cannot cross.
3. **Consume the plot unit**: When building the card, read the plot units named by “Comparable Plot Reference” in this batch's card (≤3 files, including structural distribution/plot-beat index), map beats to chapters, and replace source material. Later batches in the same unit share the card's fixed conclusions and do not reread the unit. If the current volume outline lacks required plot-unit fields, complete it first; do not enter daily writing with missing fields.
4. **End-of-batch structural review** (mandatory after every outline batch): Follow the existing outline process to confirm chapter targets use the `visible_chars_v1` metric and that core fields, prohibited early releases, and executable plot beats are complete. Never use “a fixed number of words per plot beat” to predict capacity or automatically add events. After saving each chapter outline, run `node scripts/check-outline-contract.js --json --project {书目录} --chapter {N}`. For exit 1, repair only fields named in `repair_scope` and revalidate, for no more than two rounds. **Missing fields in old chapter outlines are normal; do not copy the field set from existing files in the directory**—use this section's template. The checker still makes no semantic judgments.

Do not force thirty complete chapter outlines into one conversation.
If the book is short (≤30 chapters), Phase 3 may create them all at once.

```
## 细纲（第 N 章）

### 第 N 章：{章名}
- 核心事件：{一句话；供日更与导入统一消费}
- 字数目标：{X} 字
- 字数口径：visible_chars_v1
- 阶段位置：{开篇期/发展期/高潮期/收尾期；第X阶段第Y章；本章在阶段内承担什么}
- 单元ID/位置：{卷纲剧情单元ID；单元内第几拍/承担功能}
- 目标情绪：{具体情绪前状态→后状态；本章推进单元情绪引擎的哪一环；不得只写“热血/悲伤”等标签}
- 主角目标/关键选择：{主角本章要什么；必须做出的判断或选择}

- 本章结构公式：{节点1（目的） + 节点2（目的） + 节点3（目的） + 节点4（目的）}
- 章首钩子：{从章首7式中选择} — {具体内容；低压/过场章可写“弱钩子/仅情绪钩子，功能是…”}
- 爽点：{本章爽点；低压/修炼/过场章可写“无显性爽点，功能是…”，但仍须给读者一个往下看的理由}
- 本章禁止提前释放：{后续阶段核心真相/底牌/关系结论/终局矛盾；没有就写“无”}
- 契约风险：{契约安全/需补强/契约破坏；逐章只按七检⑥⑦复核后填写，批次级已答全表}

#### 内容概括（五段式）
- 起因：{本章事件为什么发生}
- 发展：{冲突如何推进}
- 转折：{信息/关系/局势哪里改变}
- 高潮：{本章情绪或动作峰值}
- 结尾：{本章最后落在谁的什么动作/画面/台词上——写具体落点，不写"尘埃落定""一切结束"式状态判词}

#### 情节安排（多线）
- 主线推进：{本章对主目标的推进}
- 辅线推进：{可写“无”，不能凭空制造}
- 事件线 / 任务线：{外部事件链}
- 任务卡点（如适用）：{角色要办什么事 → 卡在哪里 → 卡出什么变化 → 删掉后损失 → 收束动作；没有就写“无”，不强补}
- 感情线 / 关系线：{无显性感情线时写“无显性，但关系变化为…”}
- 逻辑线：原因 → 行动 → 结果 → 后果/新问题

#### 人物关系和出场顺序
```

**Detailed-outline quality requirements**: Every outline must directly guide manuscript prose under the current blueprint (complete stage position, structural formula, prohibited early releases, content summary, plot arrangement, character relationships/order of appearance, plot elaboration, and ending design), but **intensity follows chapter positioning rather than peaking every chapter**. Low-pressure/relationship/training/information-organization chapters may have no explicit payoff and only a weak or emotional hook; their purpose (breathing room, relationship, setup, transition) must be fully realized.
